\subsection{Automated Design of Approximate Accelerators}

The automated design of approximate accelerators involves two closely related tasks: developing arithmetic units with different error characteristics and hardware costs, and determining how to combine these units within a complete accelerator.
EvoApprox8b~\cite{mrazek2017evoapprox} targets ASIC implementations and contains 430 nondominated 8-bit approximate adders and 471 nondominated 8-bit approximate multipliers.
SMApproxLib~\cite{ullah2018smapproxlib}, in contrast, targets FPGAs and is the first open-source library of FPGA-based approximate multipliers.
Rather than selecting components from a predefined library, ABACUS~\cite{nepal2014abacus} applies approximation transformations directly to behavioral hardware descriptions to identify Pareto-optimal designs in the accuracy--power tradeoff.
These approaches define searchable design spaces through either component selection or design transformation.

Candidate evaluation is a key factor in determining how many configurations can be explored.
AutoAx~\cite{mrazek2019autoax} trains system-level prediction models using the hardware and error characteristics of arithmetic units.
It evaluates configurations through these surrogates during combinatorial search and performs ground-truth evaluations of the shortlisted candidates.
AxHLS~\cite{castrogodinez2020axhls} integrates approximate functional units with high-level synthesis (HLS), using analytical models to estimate resource requirements and design accuracy.
For FPGAs, ApproxFPGAs~\cite{prabakaran2020approxfpgas} investigates the adaptation and exploration of approximate arithmetic components originally developed for ASICs, using machine learning to reduce the time required to identify an optimal set of approximate components for FPGA implementation.
Xel-FPGAs~\cite{prabakaran2023xelfpgas} adopts a multistage design flow in which basic arithmetic components are composed into approximate functional modules, which are subsequently used for system-level optimization.

\subsection{Hardware Performance and Output Quality Modeling}

System-level performance prediction requires relating local operation characteristics to the dependencies within a design.
Graph representations provide a natural basis for modeling these relationships.
Wu et al.~\cite{wu2022hls_gnn} represent C/C++ programs as graphs, introduce a benchmark suite of 40,000 synthesizable C programs, and develop a hierarchical GNN for hardware performance prediction.
SNS~\cite{xu2022sns} predicts area, power, and timing from RTL designs.
It extracts a graph intermediate representation (GraphIR) from Verilog, uses a lightweight Transformer model, Circuitformer, to predict path-level PPA, and aggregates these predictions into circuit-level estimates through a simple multilayer perceptron (MLP).
By extending model inputs from aggregate statistics to structured design representations, these methods enable models to learn how local operations relate to the overall hardware implementation.

The organization of structural information should also reflect the prediction target.
PowerGear~\cite{lin2022powergear} incorporates activity information and connectivity between operations into a heterogeneous edge-centric graph model.
Its edge-centric neighborhood aggregation captures edge semantics and structural properties for power estimation in HLS-based FPGA designs.
For delay modeling, the mapping of operations to hardware resources and the order of signal propagation are particularly important.
Ustun et al.~\cite{ustun2020delay} use GNNs to identify operation-to-resource mapping patterns on FPGAs to support operation delay prediction.
Guo et al.~\cite{guo2022timingpredict} introduce TimingPredict for pre-routing timing prediction, using edge-delay prediction as a local auxiliary task to improve model performance.
Compared with generic graph-level aggregation, these methods incorporate target-specific hardware dependencies into the modeling process.

Approximate accelerators also require models of how arithmetic errors affect application outputs.
Mo et al.~\cite{mo2024errorfeatures} study the relationship between the error characteristics of approximate multipliers and accuracy loss in neural network inference.
They rank statistical error features by importance and use these features to predict the inference accuracy loss induced by approximate multipliers.

Hardware cost features and numerical error features serve different modeling purposes.
Our prior work, ApproxPilot~\cite{zhang2025approxpilot}, combines structural modeling with error characterization.
It represents arithmetic units as nodes and their connections as edges, encoding unit-level PPA, operation types, and error metrics as node features.
To capture the path dependence of delay, ApproxPilot adopts a two-stage model.
The first stage performs node-level classification to identify arithmetic nodes on the critical path.
The second stage augments the original node features with the classification results and performs graph-level regression to predict accelerator PPA and output quality.
The critical-path node labels are obtained from synthesis reports.
Together, these studies demonstrate the value of circuit structure for fast performance estimation and highlight the importance of path information in delay modeling.

\subsection{Surrogate Model Adaptation and Prediction Calibration}

Model adaptation seeks to transfer learned representations and predictive mappings to new target designs.
ApproxGNN~\cite{vlcek2025approxgnn} learns transferable component representations by jointly training a component embedding network and a system-level prediction network.
The embedding network processes gate-level Verilog descriptions of approximate arithmetic units to generate feature vectors.
The prediction network operates on the accelerator graph, using component embeddings and structural information to predict quality of results (QoR) and hardware cost.
For each training batch, the embedding network first processes the entire component library, and the resulting embeddings are inserted into the accelerator graph as node features.
Gradients propagate through both networks, allowing the embedding network to be trained despite the limited number of distinct components in the library.

In its transfer experiments, ApproxGNN constructs a source-domain dataset, denoted 16K, from randomly generated $3 \times 3$ convolution accelerators.
The trained models are then transferred to the Small Gaussian and Large Gaussian filters, neither of which is included in the source-domain dataset.
To mitigate systematic underestimation of PSNR after transfer, a uniform additive offset is estimated from a small set of randomly selected target samples.
This correction leaves pairwise prediction differences and candidate rankings unchanged.
ApproxGNN also investigates target-domain fine-tuning, either updating only the system-level prediction network or jointly updating the component embedding and prediction networks~\cite{vlcek2025approxgnn}.

\subsection{Design Space Exploration}

In surrogate-assisted DSE, the training dataset can be updated as the search progresses.
ParEGO~\cite{knowles2006parego} addresses multiobjective optimization with expensive evaluations by combining the objectives through augmented Tchebycheff scalarization, fitting a Gaussian process surrogate, and selecting new evaluation points using expected improvement.
HyperMapper 2.0~\cite{nardi2019hypermapper} handles design spaces with discrete variables and unknown feasibility constraints through separate regression models for objective values and classification models for feasibility.
It has been applied to the automatic tuning of hardware accelerators expressed in the Spatial programming language.
TuRBO~\cite{eriksson2019turbo} builds Gaussian process models within local trust regions, adapts the size of each region according to optimization progress, and allocates evaluation resources among multiple local searches.
These methods provide a general foundation for surrogate-assisted optimization.

Hardware design studies further integrate these iterative optimization methods with domain-specific design variables and evaluation flows.
Reagen et al.~\cite{reagen2017bayesopt} use multiobjective Bayesian optimization to explore the tradeoff between inference accuracy and energy consumption in deep neural network accelerators, treating numerical precision as a design variable.
BOOM-Explorer~\cite{bai2021boomexplorer} targets the RISC-V BOOM microarchitecture and combines active learning, deep-kernel Gaussian processes, and multiobjective Bayesian optimization.
Its acquisition function is based on expected improvement in Pareto hypervolume.
For systems integrating multiple accelerators, ARS-Flow~\cite{huang2024arsflow} combines Pareto-region random resampling with a multiobjective genetic algorithm whose hyperparameters are controlled adaptively.
Building on this framework, ARS-Flow 2.0~\cite{huang2025arsflow2} uses particle swarm optimization to enhance Gaussian process regression and iteratively updates the surrogate through active learning and Pareto-region resampling.
These studies link the selection of designs for ground-truth evaluation to the regions of the design space that are most relevant to optimization.

ApproxPilot-SE builds on this sequential optimization foundation by coupling measured-reference local calibration with surrogate updates during approximate-accelerator DSE.
Each new measurement expands both the training set and the local reference set, supporting global model updates and differential delay correction for subsequent candidates.


\section{ApproxPilot-SE Methodology}
\label{sec:method}

\begin{figure*}[t]
    \centering
    \includegraphics[width=0.98\textwidth]{figures/framework_updated.pdf}
    \caption{Overview of ApproxPilot-SE. The framework combines surrogate prediction, local latency calibration, and iterative feedback. Measured results update the surrogate models and calibration references. Final DSE produces a Pareto front and representative designs based on measured PPA and accuracy.}
    \label{fig:framework}
\end{figure*}



ApproxPilot-SE is an automated framework for approximate design optimization of domain-specific accelerators, as shown in Fig.~\ref{fig:framework}. Given a target RTL design and an approximate arithmetic-unit library, the framework explores different arithmetic-unit configurations to improve hardware efficiency while maintaining application accuracy. Graph-based surrogate models are used to estimate the PPA and accuracy of candidate designs, while real evaluation results are used to update the models and guide subsequent exploration. 

\subsection{Problem Formulation}
\label{subsec:problem_formulation}

Approximate accelerator design aims to improve hardware efficiency while maintaining application accuracy. Given a target RTL design and an approximate arithmetic-unit library, the optimization task is to select a suitable implementation for each configurable arithmetic site. Different combinations of arithmetic units produce different trade-offs between PPA and accuracy.

Before constructing the design space, we prune the arithmetic-unit library using the strategies adopted in ApproxPilot~\cite{zhang2025approxpilot}. Each unit is characterized by its arithmetic error, area, power, and latency. Dominated units are removed through multiobjective comparison. The remaining units form the candidate library for design optimization.

Let $N$ be the number of configurable arithmetic sites. For site $i$, let $e_i$ denote its exact implementation and $\mathcal{A}_i$ the set of compatible approximate implementations after pruning. The legal implementation set and the complete design space are defined as
\begin{equation}
    \mathcal{C}_i = \{e_i\} \cup \mathcal{A}_i,
    \qquad
    \Omega = \prod_{i=1}^{N}\mathcal{C}_i.
    \label{eq:se_configuration_space}
\end{equation}
A candidate design is represented by $\mathbf{x}=(x_1,\ldots,x_N)\in\Omega$, where $x_i$ specifies the implementation selected for site $i$.

Each configuration has its own area $A(\mathbf{x})$, power $P(\mathbf{x})$, latency $L(\mathbf{x})$, and application accuracy $ACC(\mathbf{x})$. Let $A_{\mathrm{ex}}$, $P_{\mathrm{ex}}$, and $L_{\mathrm{ex}}$ denote the PPA metrics of the fully exact design. We formulate the optimization problem as
\begin{equation}
    \min_{\mathbf{x}\in\Omega}
    \mathbf{f}(\mathbf{x}) =
    \left(
        \frac{A(\mathbf{x})}{A_{\mathrm{ex}}},
        \frac{P(\mathbf{x})}{P_{\mathrm{ex}}},
        \frac{L(\mathbf{x})}{L_{\mathrm{ex}}},
        1-\mathrm{Acc}(\mathbf{x})
    \right).
    \label{eq:se_search_objectives}
\end{equation}

Here, larger values of $ACC(\mathbf{x})$ indicate higher accuracy. The first three objectives minimize normalized PPA, while the fourth maximizes accuracy. The goal is to find competitive configurations with different PPA and accuracy trade-offs.

\subsection{Framework Overview}
\label{subsec:framework_overview}

Fig.~\ref{fig:framework} presents the overall framework of ApproxPilot-SE. It consists of two stages: surrogate co-evolution and final DSE.

The framework takes the target RTL and the pruned arithmetic-unit library as inputs. It first constructs a configuration-aware graph from the circuit topology and arithmetic implementation choices. Each arithmetic operation is represented by a node, and edges describe the connections between operations. Different configurations share the circuit topology but have different node features.

Based on the graph representation, ApproxPilot-SE builds separate GNN-based surrogate models for PPA and accuracy prediction. The PPA model predicts area, power, and latency. The accuracy model estimates application accuracy. A path-aware readout is incorporated into the PPA model to support latency prediction. The model structures are presented in Section~\ref{sec:surrogate_modeling}.

The co-evolution stage starts with an initial set of evaluated configurations. Their measured PPA and accuracy values are used to train the surrogate models. These configurations also provide references for local latency calibration.

During DSE, NSGA-III searches the design space using surrogate predictions. The models estimate the objectives of candidate configurations without requiring synthesis for every design. Local latency calibration adjusts the predicted latency using nearby measured configurations. The calibrated latency is combined with the predicted area, power, and accuracy to guide the search.

The search results are then used to select Pareto-relevant configurations for logic synthesis and accuracy evaluation. The resulting measurements are added to the training data, and both surrogate models are updated. Meanwhile, the measured configurations are added to the reference set for local latency calibration.

The updated models and references guide the next round of DSE. In this way, search and surrogate learning evolve together. DSE identifies configurations for real evaluation, while the new measurements improve the models used in subsequent search rounds.

After co-evolution, the updated surrogate models and calibration references are used for final DSE. NSGA-III searches the design space and selects promising configurations for logic synthesis and accuracy evaluation. The measured results are used to identify the Pareto front under the required accuracy constraint. Representative designs are then selected to provide different PPA and accuracy trade-offs.

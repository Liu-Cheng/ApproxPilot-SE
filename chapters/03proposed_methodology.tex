
\section{ApproxPilot-SE Framework}
\label{sec:framework}

\begin{figure*}[t]
    \centering
    \includegraphics[width=1\textwidth]{figures/ApproxPilot_SE_Framework_Semantic.pdf}
    \caption{Overview of ApproxPilot-SE. The framework combines surrogate prediction, local latency calibration, and iterative feedback. Measured results update the surrogate models and calibration references. Final DSE produces a Pareto front and representative designs based on measured PPA and accuracy.}
    \label{fig:framework}
\end{figure*}



Approximate accelerator design must identify arithmetic-unit configurations that improve hardware efficiency while preserving application accuracy. The configuration space grows combinatorially, yet evaluating each design through logic synthesis and application execution is costly. ApproxPilot-SE addresses this challenge by starting with a small set of measured designs and using measurements collected during exploration to calibrate latency predictions and refine the surrogate models that guide subsequent search. We first formulate arithmetic-unit selection as a multiobjective optimization problem, then describe how ApproxPilot-SE solves it under a limited evaluation budget.


\subsection{Problem Formulation}
\label{subsec:problem_formulation}


Given a target RTL design and an approximate arithmetic-unit library, the optimization task is to select a suitable implementation for each configurable arithmetic site. Different combinations of arithmetic units produce different trade-offs between PPA and application accuracy.


Before constructing the design space, we prune the arithmetic-unit library using the strategies adopted in ApproxPilot~\cite{zhang2025approxpilot}. Each unit is characterized by its arithmetic error, area, power, and latency. Dominated units are removed through multiobjective comparison. The remaining units form the candidate library for design optimization.

Let $N$ be the number of configurable arithmetic sites. For site $i$, let $e_i$ denote its exact implementation and $\mathcal{A}_i$ the set of compatible approximate implementations after pruning. The legal implementation set and the complete design space are defined as
\begin{equation}
    \mathcal{C}_i = \{e_i\} \cup \mathcal{A}_i,
    \qquad
    \Omega = \prod_{i=1}^{N}\mathcal{C}_i.
    \label{eq:se_configuration_space}
\end{equation}
A candidate design is represented by $\mathbf{x}=(x_1,\ldots,x_N)\in\Omega$, where $x_i$ specifies the implementation selected for site $i$.

Each configuration has its own area $A(\mathbf{x})$, power $P(\mathbf{x})$, latency $L(\mathbf{x})$, and application accuracy $Acc(\mathbf{x})$. Let $A_{\mathrm{ex}}$, $P_{\mathrm{ex}}$, and $L_{\mathrm{ex}}$ denote the PPA metrics of the fully exact design. We formulate the optimization problem as
\begin{equation}
    \min_{\mathbf{x}\in\Omega}
    \mathbf{f}(\mathbf{x}) =
    \left(
        \frac{A(\mathbf{x})}{A_{\mathrm{ex}}},
        \frac{P(\mathbf{x})}{P_{\mathrm{ex}}},
        \frac{L(\mathbf{x})}{L_{\mathrm{ex}}},
        1-\mathrm{Acc}(\mathbf{x})
    \right).
    \label{eq:se_search_objectives}
\end{equation}

Here, larger values of $Acc(\mathbf{x})$ indicate higher accuracy. The first three objectives minimize normalized PPA, while the fourth maximizes accuracy. The goal is to find competitive configurations with different PPA and accuracy trade-offs.
















\subsection{Framework Overview}
\label{subsec:framework_overview}

Fig.~\ref{fig:framework} shows how ApproxPilot-SE explores the design space $\Omega$ with a limited evaluation budget. The framework first samples and evaluates an initial set of configurations to train separate graph neural network (GNN) surrogates for PPA and application accuracy. The subsequent DSE is self-evolving: the current surrogates guide the search, and the search identifies which configurations to evaluate next. At predefined intervals, ApproxPilot-SE measures selected candidates, including promising PPA--accuracy trade-offs and designs near the accuracy boundary. These measurements supply new training labels and latency calibration references in the regions the search is exploring. The updated predictions, in turn, help the next round rank candidates and identify designs more likely to offer favorable trade-offs while meeting the accuracy constraint. Once the feedback budget is exhausted, the framework fixes the models and references, conducts a final search, and evaluates shortlisted designs to identify feasible Pareto designs. This subsection describes the search and evaluation workflow; Section~\ref{sec:surrogate_models} details the model architectures, training, and local latency calibration.

\noindent\textit{1) Initialization and surrogate-guided search:}
ApproxPilot-SE evaluates the initial configurations through logic synthesis and application execution. The resulting PPA and accuracy measurements form the initial training dataset $\mathcal{D}_0$, and the measured configurations also form the initial latency calibration reference set $\mathcal{R}_0$. NSGA-III uses the current PPA and accuracy predictions, including calibrated latency, to rank configurations and explore trade-offs without evaluating every candidate through synthesis and execution.

\noindent\textit{2) Candidate selection for evaluation:}
At each feedback round, ApproxPilot-SE prioritizes promising Pareto trade-offs and reserves part of the evaluation budget for candidates just below the predicted accuracy threshold. Evaluating candidates near this boundary helps identify feasible designs that might otherwise be discarded because of prediction errors.

Let $\mathcal{U}_t$ denote the set of unique, previously unevaluated configurations available for selection at round $t$. The predicted accuracy retention is defined as
\begin{equation}
    \widehat r_t(\mathbf{x})
    =
    \frac{\widehat{\mathrm{Acc}}_t(\mathbf{x})}
    {\mathrm{Acc}_{\mathrm{ex}}},
    \label{eq:se_predicted_retention}
\end{equation}
where $\mathrm{Acc}_{\mathrm{ex}}$ denotes the measured accuracy of the fully exact configuration. Given an acquisition threshold $\tau_{\mathrm{acq}}$, the candidates are partitioned into
\begin{equation}
\begin{aligned}
    \mathcal{U}_t^{+}
    &=
    \left\{
    \mathbf{x}\in\mathcal{U}_t
    \mid \widehat r_t(\mathbf{x})
    \ge\tau_{\mathrm{acq}}
    \right\},\\
    \mathcal{U}_t^{-}
    &=
    \left\{
    \mathbf{x}\in\mathcal{U}_t
    \mid \widehat r_t(\mathbf{x})
    <\tau_{\mathrm{acq}}
    \right\}.
\end{aligned}
\label{eq:se_feedback_partition}
\end{equation}

Candidates in $\mathcal{U}_t^{+}$ are prioritized by nondominated sorting of the predicted PPA and accuracy objectives, with crowding distance used to preserve diversity within a partially selected front. For $\mathcal{U}_t^{-}$, configurations closer to the predicted accuracy boundary receive higher priority. This allows the framework to evaluate both Pareto-relevant designs and candidates whose feasibility may be affected by prediction errors.



\noindent\textit{3) Evaluation and self-evolving feedback:}
The selected set $\mathcal{S}_t$ contains candidates from $\mathcal{U}_t^{+}$ and $\mathcal{U}_t^{-}$. Logic synthesis and application execution yield measured PPA and accuracy for these candidates. The new measurements are added to the cumulative training dataset:
\begin{equation}
    \mathcal{D}_{t+1}
    =
    \mathcal{D}_t\cup\mathcal{Y}_t,
    \label{eq:se_dataset_update}
\end{equation}
where $\mathcal{Y}_t$ contains the newly evaluated configurations and their measured labels. Both surrogate models are reinitialized and retrained on the expanded dataset. Meanwhile, the measured configurations are added to the latency calibration references:
\begin{equation}
    \mathcal{R}_{t+1}
    =
    \mathcal{R}_t\cup\mathcal{S}_t.
    \label{eq:se_reference_update}
\end{equation}
The reference residuals are then recomputed using the updated latency surrogate. This closes the feedback loop: DSE determines where new measurements are collected, and the updated surrogates and references determine how candidates are scored in the next round. As measurements accumulate in regions relevant to the search, the surrogates can better resolve trade-offs there, and the search can select more promising candidates for subsequent evaluation.


\noindent\textit{4) Final search and output:}
After the feedback budget is exhausted, ApproxPilot-SE uses the final surrogates and calibration references to shortlist configurations for separate evaluation through synthesis and application execution. Using these measurements, it identifies nondominated designs that satisfy the user-specified constraints and returns representative configurations spanning the feasible PPA--accuracy trade-offs.

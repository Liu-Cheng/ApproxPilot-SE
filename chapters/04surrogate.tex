
\section{Surrogate Models}
\label{sec:surrogate_models}

To efficiently evaluate accelerator configurations during DSE, ApproxPilot-SE employs two graph-based surrogate models. Given an accelerator configuration, the PPA model predicts its area, power, and latency, while the accuracy model estimates its application-level accuracy. These models provide fast estimates of the system-level behavior of candidate configurations without requiring logic synthesis and application-level execution for every design.

Following ApproxPilot~\cite{zhang2025approxpilot}, the target accelerator is represented as a graph in which arithmetic operations are nodes and their dependencies are edges. Different configurations share the accelerator topology, while their node features change according to the selected arithmetic units. For a configuration $\mathbf{x}$, the two graph inputs are
\begin{equation}
    G_k(\mathbf{x})
    =
    (V,E_k,X_k(\mathbf{x})),
    \qquad k\in\{P,S\},
    \label{eq:se_graph}
\end{equation}
where $P$ and $S$ denote the PPA and accuracy branches, respectively. The node set $V$ represents arithmetic operations, $E_k$ describes their dependencies, and $X_k(\mathbf{x})$ contains the configuration-dependent features.

The two surrogate models use different graph structures and features to capture hardware cost and application accuracy. The PPA model uses circuit structure and unit-level hardware characteristics to predict area, power, and latency. The accuracy model additionally uses arithmetic error characteristics to estimate the effect of approximation on application outputs. \subsection{Area and power}
\label{subsec:Area and power}

The PPA surrogate uses a GNN to learn circuit representations from the graph structure and node features described above. The graph encoder propagates information along directed dependencies to capture interactions between arithmetic operations.

Area and power are predicted using separate graph-level readouts. Each readout aggregates the encoded node representations for its corresponding objective. The resulting representation is combined with configuration-level features and passed to an independent regression head to predict system-level area or power.






\subsection{Latency}
\label{subsec:latency}
Unlike area and power, latency depends strongly on the paths formed by connected arithmetic operations. To improve latency prediction, ApproxPilot-SE combines a path-aware readout with local calibration using previously measured configurations.


\noindent\textit{1) Local Calibration:}
ApproxPilot-SE further calibrates the predicted latency using previously measured configurations.

At feedback round $t$, let $\mathcal{R}_t$ denote the set of configurations with measured latency in the cumulative training set. For each reference $\mathbf{r}\in\mathcal{R}_t$, its prediction residual is
\begin{equation}
    \rho_t(\mathbf{r})
    =
    L(\mathbf{r})
    -
    \widehat L_t(\mathbf{r}),
    \label{eq:se_reference_residual}
\end{equation}
where $L(\mathbf{r})$ denotes the measured latency and $\widehat L_t(\mathbf{r})$ is the current surrogate prediction.

Configuration proximity is measured by Hamming distance:
\begin{equation}
    d_H(\mathbf{x},\mathbf{r})
    =
    \sum_{i=1}^{N}
    \mathbb{I}[x_i\neq r_i],
    \label{eq:se_hamming_distance}
\end{equation}
where $\mathbb{I}[\cdot]$ is the indicator function and $N$ is the number of configurable arithmetic sites.

For an unevaluated configuration $\mathbf{x}$, the nearest measured reference is
\begin{equation}
    \mathbf{r}_t^*(\mathbf{x})
    \in
    \arg\min_{\mathbf{r}\in\mathcal{R}_t}
    d_H(\mathbf{x},\mathbf{r}).
    \label{eq:se_nearest_anchor}
\end{equation}

Let $d_{\max}$ denote the maximum calibration distance. The calibrated latency estimate is
\begin{equation}
    \widetilde L_t(\mathbf{x})
    =
    \begin{cases}
    L_{\mathrm{ex}},
    &\mathbf{x}=\mathbf{x}_{\mathrm{ex}},\\[2pt]
    \widehat L_t(\mathbf{x})
    +\rho_t(\mathbf{r}_t^*),
    &d_H(\mathbf{x},\mathbf{r}_t^*)\le d_{\max},\\[2pt]
    \widehat L_t(\mathbf{x}),
    &\text{otherwise}.
    \end{cases}
    \label{eq:se_latency_calibration}
\end{equation}

 If no reference lies within the calibration neighborhood, the direct surrogate prediction is used.

For a candidate with an applicable reference, Eq.~\ref{eq:se_latency_calibration} becomes
\begin{equation}
    \widetilde L_t(\mathbf{x})
    =
    L(\mathbf{r}_t^*)
    +
    \widehat L_t(\mathbf{x})
    -
    \widehat L_t(\mathbf{r}_t^*).
    \label{eq:se_difference_calibration}
\end{equation}

The first term provides a measured latency anchor. The remaining terms estimate the latency difference between the candidate and the reference.

To examine the calibration effect, define the original prediction error as
\begin{equation}
    e_t(\mathbf{x})
    =
    \widehat L_t(\mathbf{x})-L(\mathbf{x}).
    \label{eq:se_direct_error}
\end{equation}

Substituting Eq.~\ref{eq:se_difference_calibration} gives
\begin{equation}
    e_{\mathrm{cal},t}(\mathbf{x})
    =
    e_t(\mathbf{x})
    -
    e_t(\mathbf{r}_t^*).
    \label{eq:se_calibrated_error}
\end{equation}

Thus, the calibrated prediction error is the difference between the errors of the candidate and its reference. Suppose neighboring configurations share a common bias component $b_t$:
\begin{equation}
\begin{aligned}
    e_t(\mathbf{x})
    &=b_t+\delta_t(\mathbf{x}),\\
    e_t(\mathbf{r}_t^*)
    &=b_t+\delta_t(\mathbf{r}_t^*).
\end{aligned}
\label{eq:se_bias_decomposition}
\end{equation}

The calibrated error then becomes
\begin{equation}
    e_{\mathrm{cal},t}(\mathbf{x})
    =
    \delta_t(\mathbf{x})
    -
    \delta_t(\mathbf{r}_t^*).
    \label{eq:se_bias_cancellation}
\end{equation}

The shared bias is canceled, leaving the difference between the local error components. This provides the basis for using nearby measured configurations to correct latency estimates.





\noindent\textit{2) Path-Aware Readout:}
To capture arithmetic dependencies in latency prediction, we apply a path-aware readout to the node representations produced by the PPA encoder. Inspired by max-plus propagation in timing analysis, the readout accumulates hidden representations along arithmetic dependencies in topological order:
\begin{equation}
\mathbf{s}_v=
\begin{cases}
\mathbf{h}_v, & \operatorname{Pred}(v)=\varnothing,\\
\mathbf{h}_v+\displaystyle\max_{u\in\operatorname{Pred}(v)}
\mathbf{s}_u, & \text{otherwise},
\end{cases}
\label{eq:se_path_aggregation}
\end{equation}
where $\mathbf{h}_v$ is the representation of node $v$, and $\operatorname{Pred}(v)$ denotes its predecessor nodes in the PPA graph $G_P$. The maximum is applied element-wise. The graph-level path representation is obtained as
\begin{equation}
    \mathbf{z}_L=\max_{v\in V}\mathbf{s}_v,
\end{equation}
and used for latency prediction without requiring explicit critical-path labels.








\subsection{Accuracy}
\label{subsec:accuracy}

Application-level accuracy is determined by how local approximation errors propagate through the accelerator and affect its outputs. ApproxPilot-SE employs a separate GraphSAGE model to capture this relationship using the application graph and approximation-related features described above. The model learns how arithmetic-unit assignments and their error characteristics affect the overall application accuracy.

For a given configuration $\mathbf{x}$, the model predicts SSIM for each evaluation image. The configuration-level accuracy is obtained by averaging these predictions:
\begin{equation}
    \widehat{\mathrm{Acc}}(\mathbf{x})
    =
    \frac{1}{M}
    \sum_{j=1}^{M}
    \widehat{\mathrm{SSIM}}_j(\mathbf{x}),
    \label{eq:se_accuracy_prediction}
\end{equation}
where $M$ is the number of evaluation images and $\widehat{\mathrm{SSIM}}_j(\mathbf{x})$ denotes the predicted SSIM for image $j$. The resulting accuracy estimate is used together with the PPA predictions during DSE.
